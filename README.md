# amaru-uplc-utils

Three small tools for running the test cases produced by
`generate-conformance-tests` through [Amaru's UPLC
implementation](https://crates.io/crates/amaru-uplc).

`amaru-uplc` requires a nightly toolchain (it uses
`#![feature(allocator_api)]`). The checked-in `rust-toolchain.toml` selects one
automatically with rustup. See [BUILDING.md](BUILDING.md) for the full toolchain
setup, how to generate test cases and troubleshooting. To build immediately:

```console
$ cargo build --release
```

## `run-flat`

Decode one flat-encoded UPLC program, evaluate it, and print the result.

```console
$ ./target/release/run-flat case.flat [v1|v2|v3]
program version: 1.0.0
budget: ({cpu: 322508180
| mem: 3581})
evaluation: success
result (flat): 0100004a21
```

The optional argument selects the Plutus version whose semantics and default
cost model are used (default `v3`). The result is printed flat-encoded, so it
can be compared byte-for-byte with a `.flat.expected` file. Exits with status 1
if the program fails to evaluate, 2 for usage or decoding errors.

## `run-uplc`

Parse one textual UPLC program, evaluate it, and print the result.

```console
$ ./target/release/run-uplc case.uplc [v1|v2|v3]
program version: 1.0.0
budget: ({cpu: 351556
| mem: 1016})
evaluation: success
result (flat): 0100004821287ba8...
```

`amaru-uplc` has a textual parser but no textual printer, so the result is
printed flat-encoded. For a case generated in both formats this is the same
hex that `run-flat` prints for the `.flat` version of the same program. The
optional argument selects the Plutus version (default `v3`). Exit status is 1
if evaluation fails, 2 for usage, parse or I/O errors.

## `run-conformance`

Walk a tree produced by `generate-conformance-tests` and check every case.

```console
$ ./target/release/run-conformance /tmp/cases
checked 717 cases: 717 passed, 0 failed
```

For each case directory containing `<case>.flat` and/or `<case>.uplc`, it:

1. decodes (or parses) the program and evaluates it with Amaru;
2. compares the outcome with `<case>.flat.expected` / `<case>.uplc.expected`,
   which is either a flat/textual program or one of the markers `evaluation
   failure`, `out of budget`, `parse/decode error`;
3. unless `--no-budgets` is given, compares the consumed budget with
   `<case>.budget.expected`.

Options:

| Option | Meaning |
| --- | --- |
| `--plutus-version v1\|v2\|v3` | Semantics and default cost model to use. Defaults to `v3`. |
| `--no-budgets` | Compare only results, not budgets. |
| `--filter TEXT` | Only run cases whose path contains `TEXT`. |
| `--verbose` | Print a line for every passing case as well. |

Exit status is 1 if any case fails, 2 for usage or I/O errors.

With `amaru-uplc` 0.6.0 and Plutus V3, the default cost model matches the
reference implementation's testing parameters, so the budget files agree for
the cases generated by `generate-conformance-tests` (checked on the integer,
bitwise, BLS12-381 and ordering properties). If a cost model changes, run with
`--no-budgets` while investigating.

The generated cases are written with textual UPLC version 1.0.0. Decoding uses
`ProtocolVersion::default()`; both `.flat` and `.uplc` inputs are supported.
